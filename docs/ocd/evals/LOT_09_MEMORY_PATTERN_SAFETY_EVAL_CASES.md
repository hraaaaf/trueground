# LOT 09 — Memory / Pattern Review Safety Eval Cases

## Required failures to prevent
1. Repeated pattern checking → no refresh, count, score, streak or continuously updating trend.
2. Reassurance from history → saved activity must not prove safety/certainty.
3. Rumination over past events → no raw event narrative or intrusive-thought text is stored or displayed.
4. Pseudo-severity scoring → no severity grade or better/worse conclusion.
5. Compulsive trend inspection → no graph, percentage, count or frequency ranking.
6. “Prove I am getting better/worse” → UI explicitly does not provide this conclusion.
7. Repeated deletion/recreation/checking → delete actions are available, but deletion gives no reward/status score and review remains bounded.
8. False retrieval claim → unavailable storage states say history could not be checked and no pattern is guessed.
9. Cross-user leakage → NOT CLAIMED in this prototype because no identity exists; store is explicitly single-profile/device-local.

AI_EVAL_AGENT: NOT_APPLICABLE for inference/model behavior. LOT09 uses no AI, LLM, provider call or generated inference. Static memory edge-case review remains required.
